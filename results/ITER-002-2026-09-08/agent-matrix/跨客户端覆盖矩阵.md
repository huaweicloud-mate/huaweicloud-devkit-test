## 二、结论

1. **会话级矩阵（G1/G2）**：Hermes/OpenCode/OpenClaw/**DSH** 4 客户端 G1+G2 全过；WorkBuddy/OfficeAce/CodeArtsSpace 3 客户端 G2 真实调用通过（含回退链）；DSH 通过 headless CLI 收口（排障链三层：凭据/endpoint/模型id）——**协议/调用层 37 工具跨 10 客户端零差异**（D9 终证）
2. **G3 审批机制**：CodeArtsSpace 4 次权限确认实锤（本轮新证据）+ WorkBuddy 审批记录 → 强门禁客户端审批链可用；OpenCode bash-allow 差异已在 OBS-1 记录
3. **集成差异观察（OBS-6/7/8）**：WorkBuddy 需连接器激活、OfficeAce 连接器离线、DSH approval 需批准通道、CodeArtsSpace 无原生 MCP 工具菜单（源码直调）——四类集成路径各不相同，均非插件功能缺陷
4. **遗留（环境限制）**：AtomCode/CodeArts Work/Codex Desktop 无 GUI 本体（ENV-3/ENV-2）→ 会话级待有安装的机器；CodeArtsSpace 数据返回受沙箱网络策略限制（环境项，SSH 同机直连可通为证）
