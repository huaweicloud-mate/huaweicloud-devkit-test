- 包内 `.agents/plugins/marketplace.json` 的 marketplace 名称为 `huaweicloud-devkit`。
- 包内 `.codex-plugin/plugin.json` 的插件名为 `huaweicloud-devkit`。

- 隔离 `USERPROFILE` 下执行 `install --target codex` 后，未生成 `.config/opencode/huaweicloud-plugins`。

验证点 3：安装失败是否非零退出且不误报成功。

- 代码路径显示：`installCodex()` 对 marketplace/add plugin 非零状态返回 `false`，`cmdInstall()` 收集 `installFailures` 后会 `process.exit(1)`。
- 本轮尝试用 Windows `.cmd` fake Codex CLI 模拟 `codex plugin add` 失败，但 `.cmd` harness 自身在 `exit /b 7` 后仍被 Node `spawnSync(..., shell:true)` 识别为状态 0，不能作为产品缺陷证据。

结论：需补充真实失败场景或更可靠 harness 复验。当前不能判定失败处理已完全闭环，也不能将本次模拟结果作为失败证据。

## 5. 识别出的其他问题 / 风险

### 5.1 Codex CLI 注册状态检测仍匹配旧插件名

位置：`plugins/huaweicloud-core/src/auth/agent-registration.mjs`

当前逻辑：

```js
return out.includes('huaweicloud-core');
```

风险：`codex plugin list` 新插件显示为 `huaweicloud-devkit@huaweicloud-devkit`。该检测仍只匹配旧名，可能导致 `auth status` / 注册状态类能力误报 Codex 未配置。

建议：同时匹配 `huaweicloud-devkit@huaweicloud-devkit`、`huaweicloud-devkit`，并保留 `huaweicloud-core` 作为旧版本兼容。

### 5.2 Codex Desktop marketplace 相对路径疑似不一致

隔离安装结果：

- 实际插件目录：`%USERPROFILE%\plugins\huaweicloud-devkit`
- marketplace 文件：`%USERPROFILE%\.agents\plugins\marketplace.json`
- marketplace source path：`./plugins/huaweicloud-devkit`

如果 Codex Desktop 将该相对路径按 marketplace 文件所在目录解析，则目标会变成 `%USERPROFILE%\.agents\plugins\plugins\huaweicloud-devkit`，与实际安装目录不一致。

风险：Desktop UI 可能在“个人插件”中找不到实际插件，或安装失败。

建议：用真实 Codex Desktop UI 验证路径解析规则；若按 marketplace 文件目录解析，应改为绝对路径或正确相对路径（例如 `../../plugins/huaweicloud-devkit`）。

### 5.3 `doctor` 失败时返回码仍为 0

隔离目录执行 `doctor --target codex`，存在多项 `[FAIL]`，但进程退出码为 0。

风险：CI/自动化脚本无法通过退出码判断 doctor 失败。

建议：doctor 存在 `fail > 0` 时设置 `process.exitCode = 1`；如需保持人工友好，可提供 `--no-fail-exit` 选项。
