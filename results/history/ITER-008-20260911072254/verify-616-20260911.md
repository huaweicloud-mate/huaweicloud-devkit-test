## 二、源码核查

### main 分支（hdkitservice-api.mjs）
```js
const headers = { 'Content-Type': 'application/json', 'X-HW-AK': ak, 'X-HW-SK': sk };
if (securitytoken) headers['X-HW-Security-Token'] = securitytoken;
```
- `X-HW-Client-Version` 出现 0 次；无任何版本传递 → **main/发布线未修复**（与 #616 body 一致）

### dev 分支
```js
const headers = {
  'Content-Type': 'application/json', 'X-HW-AK': ak, 'X-HW-SK': sk,
  'X-HW-Client-Version': readInstalledVersion() || '0.0.0',
};
```
- **已按后端契约补上 X-HW-Client-Version** → dev 修复已合入，**待进发布线**

## 三、测试环境端到端（devkit.topxtopx.com check-user）

| 试验 | HTTP | HDKIT_VERSION_TOO_OLD | 响应要点 |
|---|---|---|---|
| A 无版本 header（main 形态）| 500 | **否** | `{"code":"HDKIT_INTERNAL","message":"服务内部错误","clientVersion":null,"minVersion":null}` |
| B `X-HW-Client-Version: 1.1.1`（dev 形态）| 500 | **否** | 同上 + `"latestStable":"1.1.2","updateAvailable":true,"upgradeHint":"检测到 huaweicloud-devkit 新版本 1.1.2，建议升级"` |

### 判定
1. **min 门槛关闭生效**（对应测试环境运维处置：`UPGRADE_MIN_VERSION` 不配置）——两种请求均不再被 409/版本硬拦截，改走软提醒（与 zrr000212 评论「无头/非最新 → 200 软提醒」一致；本实测为 500，但**版本拦截层已消失**）
2. **X-HW-Client-Version 契约生效**——带 header 时后端解析出客户端版本并返回 `upgradeHint`（B 响应含 minVersion:null + updateAvailable:true，证明版本链贯通）
