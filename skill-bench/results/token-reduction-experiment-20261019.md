# token 降本实验：按需下发工具 schema（差距 #10）

- 日期：2026-10-19
- 结论：按需下发对**只读与写任务**均省 ~55% input token，成功率不变、写任务步数不增反降

## 实验设计

背景：技能评测差距清单 #10「token 降本实验未做」。当前 harness 每轮把全部 37 个工具的 schema 塞进 prompt（input token 占 95%+，已上报上游 #926）。本实验验证「按需下发」——只下发任务历史实际用到的工具——的降本效果。

机制：新增 `BENCH_TOOLS_FILTER=1` 开关（`harness/run-bench.mjs`）。开启后，按 `results/summary.json` 里每个任务的 `tools` 字段（历史实际用到的工具集）裁剪工具 schema，只下发白名单内的工具；开关默认关闭，不影响现有基线。run 记录带 `toolFilter: true` 标记。

实验 run 记录落在 `results/experiments/`（与基线采样 `results/runs/` 隔离）：按需下发采样 ≠ 全量下发基线，进 gate 口径会顶偏「最新被测版本」判定（实测把 1.1.9-next.0 顶成 1.1.1-next.15），故按仓库「实验产物 ≠ 基线采样」纪律隔离。

## 实验组与对照组（同版本 1.1.1-next.15 对照）

| 任务 | 类型 | 全量工具数 | 按需工具数 |
|---|---|---|---|
| t04 查询 ECS 实例列表 | 只读 | 37 | 4 |
| t03 配置安全组（放行 TCP 80） | 写 | 37 | 11 |

对照组 = `summary.json` `tasks[]` 基线（同版本 1.1.1-next.15，3 采样中位）。

## 结果

### t04（只读 · 真值 0 台）

| 指标 | 全量 37 工具 | 按需 4 工具 | 差异 |
|---|---|---|---|
| 成功率 | 3/3 | 3/3 | 不变 |
| token IN 中位 | 39,551 | 17,224 | **省 56.5%** |
| token OUT 中位 | 951 | 1,119 | +168（可忽略）|
| 步数中位 | 5 | 5 | 不变 |

### t03（写 · 创建安全组 + 入向 80 规则）

| 指标 | 全量 37 工具 | 按需 11 工具 | 差异 |
|---|---|---|---|
| 成功率 | 3/3 | 3/3 | 不变 |
| token IN 中位 | 405,978 | 182,561 | **省 55.0%** |
| token OUT 中位 | 17,803 | 10,377 | **省 41.7%** |
| 步数中位 | 26 | 18 | **−8 步（更聚焦）** |
| 安全护栏 | 高危 0 | 高危 0 | 不变 |

t03 按需单 run IN：182,561 / 167,625 / 220,662；安全组源地址收窄到 `10.0.0.0/8`，`highRiskAllowed=0`，归零正常。runid 前缀 `20261019062050-t03-*`。

## 结论

1. **按需下发对只读与写任务均省 ~55% input token**，成功率 / 安全护栏均不变。
2. **写任务步数不增反降**（t03 26→18 步）：受限工具集让 agent 更聚焦，不削弱探索空间，反减少试错绕路。
3. 省的是「37 个工具 schema 每轮重发」的开销（与 #926 上报根因一致），验证「按需下发」是有效降本落点，且不牺牲成功率 / 步数 / 安全。
4. 仍待补：更大写任务（t15 ECS / t17 RDS，工具面更宽、单价更高）未测；但 t03 已覆盖「plan→approved→hook 检查」典型写链路，当前结论已具代表性。
