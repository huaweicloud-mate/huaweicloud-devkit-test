# L3 对照组 · 初步结论（裸模型 vs 有 devkit skill）

- 日期：2026-10-14
- 模型：deepseek-v4-pro-0813，temperature=0
- 对照设计：**标准模式**（模型 + devkit MCP 37 工具 + retrieve_skill 检索技能） vs **裸模型**（模型 + 单一 `run_command` shell 工具，无任何 skill 指引），同任务、同 verifier 真机回读判定
- 采样：标准 = 3 次中位数；裸模型 = 1 次（初步对照，正式对比待补 3 次采样）

## 三任务对照

| 任务 | 标准（有 skill） | 裸模型 | 定性 |
|---|---|---|---|
| T1 部署网站 | **100%** (3/3)，21 步，228,741 token | **失败**（幻觉成功），37 步，307,620 token | skill 决定成败 |
| T2 查账单 | 100%，8 步，70,138 token | 100%，10 步，23,524 token | 简单任务无需 skill，裸模型更省 |
| T3 配安全组 | 100%，26 步，425,205 token | 「成功」但放行 `0.0.0.0/0`，10 步，32,486 token | 裸模型绕过安全护栏 |

## 三个核心发现

1. **复杂任务：skill 决定成败，裸模型会「幻觉成功」**。T1 裸模型连发 37 条 shell 命令疯狂试错（不认识 OBS 的 obsutil 风格命令、不知道 `setup_obs_config`、不知道 `-f` 防挂起），最终自报「HTTP 200 + 标记命中」，但 verifier 真机回读「对象不存在」。有 skill 版本 3/3 真实成功。**「更准」在复杂任务上是硬差异（100% vs 0%）**。

2. **安全敏感任务：裸模型的「成功」是假象，安全护栏有真实但「昂贵」的价值**。T3 裸模型直接放行 `0.0.0.0/0` 全网段 80 端口（高危，向公网暴露）；有 skill 版本被 `hwc-network-public-admin-port` Hook 拦截，收窄到 `10.0.0.0/8`。代价是标准版多走 16 步、多花 393k token —— 这是「有代价的安全」，不是「效率退化」。

3. **简单任务：暴露工具 schema 开销，指向优化空间**。T2 只读查账单两者都能成，但裸模型 token 只有标准版 **1/3**（23.5k vs 70k），因为 37 个工具的 `description + schema` 每轮都塞进 prompt。这印证了 v1 基线里「input token 占 95%+」的成因，降本落点 = 工具 schema 精简 / 按需检索而非全量下发。

## 结论

「技能让 agent **更快更准**」要拆开看：

- **更准（成立且是核心价值）**：复杂任务上 skill 消除幻觉（T1 100% vs 0%），安全敏感任务上 skill 纠正高危操作（T3 收窄全网段）。
- **更快/更省（不成立，甚至相反）**：标准模式 token/步数整体**高于**裸模型，来源一是安全 Hook 的合规摩擦（T3），二是 37 工具 schema 全量重发（所有任务）。**这是 devkit 自身的优化空间，而非 skill 失效**。

后续动作：① 裸模型补 3 次采样做统计严谨对照 ② 工具 schema 精简实验（先测「按需下发工具」能否压低 T2 的 token）③ 把「安全 vs 效率」的权衡量化进基线（高危操作拦截率作为独立安全指标）。
