## 为什么单独分区

| 维度 | 功能用例（`design/`） | UX 体验用例（本分区） |
|---|---|---|
| 判据形态 | 字段/错误码精确相等 | 症状消失（闭环）/ 独立观测 / 指标不劣化 |
| 断言强度 | 单侧 | **正断言 + 反断言**（不含英文原文、不含内部代号） |
| 执行载体 | 母版矩阵 + 脚本 | fixture / replay / agent-eval（`test/unit`、`eval/harness`、`eval/replay`） |
| 生命周期 | 长期稳定 | 提案期会大改，不宜直接进母版真源 |

## 可执行载体映射

| 层 | 载体 | 适用用例 |
|---|---|---|
| L1 单测 | `test/unit/d11-*.test.mjs` | 文案/字段/反断言类（D11-1/10/16/26） |
| L2 逐用例夹具 | `eval/harness/fixtures/d11-*.mjs` + 运行器 `run-ux.mjs`（**已落地 24 个**，与 `gen_ux.py` 的 `LANDED` 登记一致：D11-1/2/3/4/5/8/9/11/12/13/16/19/22/26/27/28/29/30/34/37/41/42/43/44 各一个夹具；共用工具 `ux-common.mjs`。其中 **D11-13 / D11-34 为真机用例**：需 `export HW_ACCESS_KEY/HW_SECRET_KEY` 后由客户端 agent 在真机执行，无真凭证时判 `BLOCKED` 计入"环境不可判定"） | 登录引导与母语化、生效账号可见、切换三元组、状态机、术语人话化、统一错误卡、IAM-401 文案、审批可解释、KooCLI 隐私协议、STS 到期可动作、输出摘要与截断、编码契约、误导归因、故障注入、登录后自检、资源归零等 |
| L3 回放对照 | `eval/replay/`（待新增 `recordings/ux-baseline-v1.jsonl`） | 体验回归量化（D11-39） |
| L4 Agent 评测 | `eval/harness/run-agent-eval.mjs` + **`eval/prompts/eval-set-ux.csv`（已落地，10 条模糊中文需求）**；三指标提取见 `eval/harness/ux-metrics.mjs`（`steps`/`fails`/`clarifications`），对照判定 `compareUxMetrics` | 度量对照（D11-40） |

> **L4 口径边界（重要）**：三指标是**启发式近似**，只用于**同 SUT「基线版 ↔ 新版」相对对照**（不劣化 + 至少一项改善），**不作绝对判定**。绝对阈值换客户端/模型即失效，相对比较可抵消输出格式差异。
> D10 的意图路由评测（`eval-set-v2.csv`）判的是「动作达标/是否走审批」；D11-40 判的是「体验三指标是否劣化」——同一 runner、不同口径。

## 已接入自动化

| 入口 | 内容 |
|---|---|
| `npm run test:ux` | D11 夹具批量运行器：**自动发现** `d11-*.mjs` + **内置宿主隔离**（空 `HOME`/`USERPROFILE`）+ 三态退出码 |
| CI job `d11-ux-fixtures` | `.github/workflows/contract-unit-tests.yml`；当前 `continue-on-error: true`（需求未实现属**已知缺口态**，先记趋势不阻断），实现到位后去掉即为硬门禁；证据 artifact `d11-ux-evidence` |

> D11 夹具**未**列入 `run-all.mjs`：run-all 是 Issue #7 批次清单且其 exit 语义为"harness 是否健康"，
> 混入长期 NOT_IMPLEMENTED 的用例会让它恒红、丧失门禁意义。UX 走专用运行器。

### 退出码语义（与"harness 坏了"区分开）

| exit | 含义 |
|---|---|
| 0 | 全部通过（需求已实现） |
| 1 | `NOT_IMPLEMENTED` —— 需求验收未达标，属**已知缺口**，非 harness 故障 |
| 2 | `BLOCKED` —— 宿主/环境不满足，结果不可判定 |

## 状态口径

- 本分区与母版同口径：**纯设计定义**（`设计状态=DESIGN_COVERED` 表示"设计完整"，**非执行通过**）；执行态统一落 `results/Summary/`。
- `依赖` 列含 `契约依赖: <字段> 待冻结` 的用例（共 11 条：D11-3/4/5/6/8/9/13/14/16/28/30）：**未落载体**的 7 条在契约冻结前应标 **NOT_RUN**，不得以 `DESIGN_COVERED` 冒充"可执行/已通过"；**已落载体**的 4 条（D11-3/4/5/30）按「门禁先行」口径先跑 —— 结果如实计为"需求未实现"、只作趋势，契约冻结后才作正式契约验收。
- 已落地可执行载体的登记处是 `gen_ux.py` 的 `LANDED` 字典（单一登记处，生成器会校验路径真实存在），共 14 条；`自动化建议` 列由它派生为 `fixture:<路径>`。

## 载体与执行

```bash
python test-cases/ux/gen_ux.py                     # 重新生成（幂等，字节可复现）

# 首选：批量跑全部 D11 夹具（自解析 hdk src + 内置宿主隔离）
npm run test:ux
npm run test:ux -- --evid <dir>                    # 同时落证据

# 备选：单跑某个夹具（需自行隔离宿主：USERPROFILE/HOME 指向空目录）
node eval/harness/fixtures/d11-37-guidance-closure.mjs <hdk src> --evid <dir>
#   exit 0 = 通过；exit 1 = 需求未实现；exit 2 = ENV_CONTAMINATED（宿主受污染，整例不可判定）
```

## 与母版的关系

- **当前唯一真源 = 本目录**（`gen_ux.py`）。
- 评审通过后并入 `design/` 母版（需同步 `gen_matrix.py` 与 `verify_new.py` 的行数门禁），届时 `design/` 恢复为唯一真源、本分区降级为归档。
