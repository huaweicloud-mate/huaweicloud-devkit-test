# #518/#566 镜像滞后文档问题（回归用例）

- **关联设计用例**：`D1-40`（镜像 lag 下检测正确性 / 反向提醒防护，P0）
- **严重级**：P1
- **状态**：已修（dev 合入 #566，仅 dev 未进 next；1.1.2/next.2 均含防倒退）
- **上游**：https://github.com/huaweicloud/huaweicloud-devkit/issues/518 、#566（修复 PR）

## 根因

README 对国内镜像滞后场景无防护说明；`judgeUpdate` 缺「远端 ≤ 本地不提示」的防倒退判断，镜像 lag 时可能提示版本倒退。

## 复现步骤

1. 设置 `npm_config_registry` 指向滞后镜像（latest 落后于官方）。
2. `queryDistTags` 取回滞后 dist-tags，`judgeUpdate(current, distTags)` 判定。
3. 对照官方源结果，观察是否出现「倒退提醒」。

## 断言契约（回归判定标准）

| # | 断言 | 期望 |
|---|---|---|
| 1 | 远端 latest ≤ current | 不提示版本倒退（`result != update_available`） |
| 2 | 官方 latest > current | 策略符合设计（正常提示 update_available） |
| 3 | 镜像返回坏 JSON | `result=check_failed`，不误报 |

**唯一断言口径**：防倒退以「远端 ≤ 本地 → 不提醒」判定，不采用"镜像可用即通过"替代。

## 证据

- `git log 306c633`（#566 合入 dev）、`update-check.mjs` judgeUpdate 防倒退逻辑。
- 待 next 发布后复验 next 线含防倒退。

## 回归结论

next 线发布后重跑 D1-40 + 上述 3 断言，全过关闭。
