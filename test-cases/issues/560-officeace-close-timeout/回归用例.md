# #560 OfficeAce 连接失败 CLOSE_TIMEOUT（回归用例）

- **关联设计用例**：INT-1（OfficeAce 连接失败，集成）——无独立设计级 ID，属客户端集成
- **严重级**：P1
- **状态**：已修（608b120 进发布线，09-08 CLOSED status/resolved）
- **上游**：https://github.com/huaweicloud/huaweicloud-devkit/issues/560

## 根因

OfficeAce 宿主在 probe 后清理阶段要求 MCP 子进程退出（stdin close），但 MCP server 设计为长驻进程，导致 `CLOSE_TIMEOUT` 连接失败。归属框架侧。

## 修复

`mcp-server.mjs` 增加 `NEEDS_KEEPALIVE = hermes && win32` 分支：hermes/win32 保持长驻，其他宿主 stdin close → `process.exit(0)`。

## 复现步骤

1. OfficeAce 环境安装插件，发起连接。
2. 观察连接结果与工具注册数。
3. 触发 probe 清理（stdin close），观察进程退出是否及时（不 hang）。

## 断言契约（回归判定标准）

| # | 断言 | 期望 |
|---|---|---|
| 1 | 连接结果 | connected |
| 2 | 工具注册 | 37 工具注册成功 |
| 3 | stdin close | 非 keepalive 宿主进程 `exit(0)` 及时退出，无 CLOSE_TIMEOUT |

**唯一断言口径**：以「connected + 工具注册 + 进程不 hang」判定，不采用"无报错即通过"替代。

## 证据

- `608b120` `mcp-server.mjs` `NEEDS_KEEPALIVE` 源码实证。

## 回归结论

已闭环（关闭）；升级/改版涉及 OfficeAce 适配时复测本契约，出现 CLOSE_TIMEOUT 即重开。
