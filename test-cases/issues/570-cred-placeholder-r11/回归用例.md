# #570 码道占位符遮蔽真实凭证 R11 归零（回归用例）

- **关联设计用例**：D2 认证维度（凭证来源/优先级负向）；占位符/脱敏值遮蔽为**新增负向场景**，建议母版新增 D2 负向用例锚定「R11 归零」（待设计阶段与 `design/` 母版对齐具体编号）
- **严重级**：P0（真实凭证被占位符遮蔽 → 云操作全失败 + 诊断误导，凭证正确性 + 功能中断）
- **状态**：未修复（方案 v5 已冻结，R11 `isPlaceholder` 代码未合入上游）
- **上游**：https://github.com/huaweicloud/huaweicloud-devkit/issues/570

## 根因

`credentials.mjs` 的 `resolveCredentials()` + `readCodeArtsCredentials()` 只用 **truthy 判断凭证**（`readCodeArtsCredentials` 里 `if (ak && sk)`，见 `credentials.mjs:197` 与 `:220`；`resolveCredentials` 里 `if (!ak && stored.ak)` 类兜底），**不识别占位符/脱敏值**。码道 IDE 市场安装把 `<HW_ACCESS_KEY>` / `<HW_SECRET_KEY>` 占位符写进 mcp_settings env，被当成有效凭证，遮蔽 S1 中用户真实凭据 → 现象「连接成功但云操作全失败」，指纹诊断误导（env 指纹 89302ef5 实为占位符哈希）。

**方案 v5 修复（R11）**：任一凭证来源（env/S1/S4）呈「模板/占位符形态」→ 置空归零，不参与优先级与指纹比对，并输出显式告警；判定函数 `isPlaceholder()`，须**先行于**码道三件套门（否则「占位符三件套」被误判为平台注入）。

## 修前基线（已实测确认，2026-09-14 11:51）

本地 hdk checkout `8bcae14`(1.1.4-next.2)；`git fetch origin dev` 后 `origin/dev=`306c6331，`git log --all -S "isPlaceholder"` **全空** → 本地与远端 dev/main 均无 `isPlaceholder` 实现。当前 `readCodeArtsCredentials` 对 `<HW_ACCESS_KEY>`/`abc****` 一律 `if (ak && sk)` 通过并返回 → bug 可复现。

## 复现步骤

1. 码道上下文：在 `process.cwd()` 下建 `.codeartsdoer/mcp/mcp_settings.json`，`mcpServers["huaweicloud-devkit"].env.HW_ACCESS_KEY="<HW_ACCESS_KEY>"`、`HW_SECRET_KEY="<HW_SECRET_KEY>"`（占位符）。
2. S1 `~/.config/huaweicloud/credentials.json` 预置真实 AK/SK（≥20 位）。
3. 调 `resolveCredentials()`，观察返回账号：修前返回占位符（bug），修复后应返回 S1 真实值或显式告警归零。

## 断言契约（回归判定标准）

### A. `isPlaceholder()` 形态判定（R11 核心）

| # | 输入形态 | 示例 | 期望判定 |
|---|---|---|---|
| 1 | 尖括号占位 | `<HW_ACCESS_KEY>` / `<your-ak>` | 归零 |
| 2 | 模板插值 | `${HW_ACCESS_KEY}` | 归零 |
| 3 | 关键词占位 | `YOUR_AK` / `REPLACE_ME` / `change.me` | 归零 |
| 4 | 脱敏值（前3位+星号） | `abc****` | 归零 |
| 5 | 真实凭证（≥20 位纯字母数字，无上述符号） | 真实 AK/SK | **不归零（视为真值）** |

### B. R11 应用点（`credentials.mjs` 四处入口统一归一）

| # | 待测点 | 期望 |
|---|---|---|
