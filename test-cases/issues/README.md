# issues 问题回归用例目录

本目录按 **issue** 归档**定向回归用例**——每个上游缺陷一条独立目录，修复后按此定向回归、回归通过才关闭。

## 归档规则

1. 目录命名：`<编号>-<slug>`（如 `554-windows-npm-einval`）。
2. 每个 issue 目录至少含 `回归用例.md`，内容固定包含：
   - **关联设计用例 ID**（指向 `design/` 母版里该缺陷的负向用例）
   - **严重级**（P0/P1/P2）
   - **状态**（未修复 / 已修复待回归 / 已回归关闭）
   - **根因**（一句话）
   - **复现步骤 + 断言契约**（回归判定标准）
   - **上游链接 / 证据**
3. 修复后**定向回归**：P0 缺陷修复后回归通过 → 关闭目录归档结论；未通过 → 追加证据。
4. P0 缺陷的回归用例同步纳入 `daily/` 基础清单（保证每天盯）。

## 与母版 / 版本的关系

- 母版 `design/` 里的负向用例（如 D1-39、D4-22/23）是**长期锚点**，本目录是**缺陷级增补**（复现细节 + 断言契约 + 修复结论）。
- 版本级缺陷清单见 `versions/<版本>/迭代测试设计.md` 的「缺陷管理」节。
