# #554 Windows 更新检测链 EINVAL（回归用例）

- **关联设计用例**：`D1-39`（Windows 升级检测链可用性，P0）/ 展开级 `EXP-NR3-09/10/11`
- **严重级**：P0
- **状态**：未修复（1.1.2 / 1.1.2-next.4 均未修，复验评论 issuecomment-5594967457 已追加上游）
- **上游**：https://github.com/huaweicloud/huaweicloud-devkit/issues/554

## 根因

`update-check.mjs` 的 `queryDistTagsSync/queryDistTags` 用 `spawnSync/ spawn('npm.cmd', ['view', ...])` **未加 `shell:true`**，Windows 下返回 `EINVAL` 且被静默吞掉（`catch` 后 debugLog），导致 `check_update` 端到端返回 `latestStable=null` —— Windows 存量用户收不到升级提醒。

对照实验：同进程加 `shell:true` → `status=0` 正常拉取 dist-tags；网络正常（镜像/官方源均可达）。

## 复现步骤

1. Windows + Node≥22，`npm config get registry` 确认源可达。
2. 直调 `queryDistTagsSync()`（无 shell:true），捕获返回值与 `error.code`。
3. 对照 `queryDistTagsSync` 加 `shell:true` 版本，比对 `status`。
4. 真实 `check_update` MCP 调用，断言 `latestStable` 非 null。

## 断言契约（回归判定标准）

| # | 断言 | 期望 |
|---|---|---|
| 1 | `queryDistTagsSync()` 返回 | 非 null（`{latest, next}`），Windows 下不 EINVAL |
| 2 | `error.code` | 不出现 `EINVAL` 静默失败 |
| 3 | 加 `shell:true` 对照 | 与无 shell 版一致 `status=0`（确认修复方向） |
| 4 | `check_update` MCP 返回 | `latestStable != null`，能正确判定 up_to_date / update_available |

**唯一错误码断言**：Windows 检测链可用性的判定只认「`status=0` 且 `latestStable != null`」，不采用日志条数或"未报错"替代。

## 证据

- `d1-uc-probe.mjs` D1-39a~d、`d1-check-update-call.mjs`、`verify-554b.mjs`（对照实验）
- 修复后回归须在**正式发布线**（非 FIX(sim)）复验 Windows 全链。

## 回归结论

修复版本发布后重跑 D1-39 + 本断言契约，全绿才关闭；当前 P0 未闭合，**每日基础用例必跑盯防**。
