## 一、自审方法：先把"体验触点"穷举出来

"覆盖用户体验"不能按工具数衡量，要按**用户旅程触点**穷举。触点来源：CLI 15 个子命令（`auth/check/doctor/help/info/install/install-hcloud/proxy/reinstall/remove/status/uninstall/update/upgrade/version`）+ 40 个 MCP 工具 + 11 个客户端目标 + 沙箱/审批/归零三条关键链路。

共抽 **42 个触点**，分 9 组（A 安装与首次使用 / B 登录与凭据 / C 日常使用 / D 风险与审批 / E 沙箱 / F 客户端差异 / G 端到端旅程 / H 隐私与信任 / I 度量）。

## 三、v1 的三类设计缺陷

### 3.1 覆盖面缺陷（偏科）

- 重"登录机制"、轻"使用过程"：E 沙箱 0 条，而沙箱恰是既有 issue #787 / #817 的故障高发区。
- 无端到端旅程：全部是"单点断言"，没有一条回答"新用户从零到第一次成功调用云资源，要几步、要不要查文档"。
- 无安装/首次使用链路：`install` 交互、KooCLI 隐私协议（首次使用**必踩**）、镜像滞后提示均未覆盖。

### 3.2 方法论缺陷

| 技术 | v1 是否有 | 说明 |
|---|---|---|
| 等价类划分 | 有 | 生效来源四态等 |
| 决策表 | 部分 | 仅 6 错误码；缺"11 客户端 × 体验触点" |
| 边界值分析 | **无** | region 非法值、指纹为空、超长输入均未测 |
| 状态转换测试 | **无** | 登录态机（未登录→已登录→切号→登出→失效）未系统化 |
| 场景法（用例法） | **无** | 端到端旅程缺失 |
| 错误推测 | **无** | HOME 不可写、弱网、磁盘满未覆盖 |

### 3.3 断言质量缺陷

1. **单侧弱断言**：v1 多处只写"含中文"，可被"中文夹杂英文原文"糊弄 → v2 升级为**双向断言**（正断言 + 反断言，例如"不含 `Access Key ID (AK): ` 原文"）。
2. **契约依赖未标注**：`effective` / `persistsAfterRestart` / `affects` / `checkup` 都是**尚未实现的新契约**，v1 却以 `DESIGN_COVERED` 呈现，易被误读为"可执行" → v2 在「依赖」列显式写 `契约依赖: <字段> 待冻结（UX-Rx）`（共 11 条）。**设计完整 ≠ 可执行**，这条口径必须双轨透明。
3. **阈值无依据**：v1 的"命中率 ≥85%"是拍的 → v2 补依据（issue #852 实测基线 21.4%）。

## 六、诚实边界：断言覆盖不到的部分

体验用例的可判定性天然弱于功能用例。本次采用的策略是**把主观体验翻译成客观可判定信号**：

| 主观体验 | 翻译为客观断言 |
|---|---|
| "提示友好" | 字符集断言（含中文）+ 反断言（不含指定英文原文） |
| "可动作" | `action` 字段以 `npx huaweicloud-devkit` / `hcloud` 开头 |
| "闭环" | `ready` / `nextStep` 字段非空且唯一 |
| "可发现" | 能力清单非空且分组覆盖三类 |
| "听得懂" | 中文意图集命中率量化 |

**仍无法用断言覆盖、只能靠人工可用性评估的三类**：
1. **认知负荷**——用户一次要理解几个新概念（AK/SK、region、project-id、S1/S2/S3）？建议用"任务完成步数 + 求助次数"度量（G-UX-21）。
2. **错误文案的"够不够用"**——断言只能证明"有下一步命令"，证明不了这步对新手够。
3. **视觉与排版**（CLI 颜色、表格对齐、客户端内渲染）——需截图/录屏人工评审。

> 建议：本套用例作为**自动化门禁**（回归防退化），另配一份**人工体验 rubric**（G-UX-21）作为**验收增量**。两者口径分开，不互相替代。

## 七、自审结论

1. v1（21 条）覆盖 22/42 触点（52%），且集中在登录段 → **不能宣称"覆盖用户体验"**。
2. v2（35 条）覆盖 30/42 触点（71%），并补齐状态转换/边界值/错误推测三类方法论空白。
3. 剩余 21 个缺口已登记（含 4 个 P1），**不虚增用例**，待评审决定归属。
4. 端到端旅程（G-UX-16）与体验度量（G-UX-21）是"提升体验"的关键缺口，建议随第一批一起补。
5. 本套用例是**回归防退化门禁**，不替代人工可用性验收。
