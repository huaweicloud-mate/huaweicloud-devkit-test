## 五、关键结论

1. **迁移用例本身契约有效**：`test-cases/versions/v2.0.0/` 冻结快照（76 迁移 + 136 原样）与 v2 契约对齐，vendor gate 三段式、dispatch 工厂函数、remote Streamable HTTP、规则集 19 条、工具面 56 的迁移断言全部取到真机结论。
2. **「v2 两大 P0」是契约问题非产品回归**：母版 v1 契约跑 v2 的 route 0% / dispatch 崩溃，改用迁移用例后均恢复，是本次测试最有价值的判定。
3. **新 P0 独立于迁移**：D4-15 URL 编码绕过写检测是 136 条原样用例在 v2 上的新发现，需产品修复 + 回归，是「不建议放行」的当前主要依据。

## 七、口径边界（不吹）

- **「契约迁移闭环」≠「v2 可放行」**：迁移论证了 76 条用例断言正确，但 D4-15（P0）等真实产品缺陷仍在前，整体结论「不建议放行」。
- **95.0% 通过率的分母不含 47 条 BLOCKED**：BLOCKED 是「缺探针/真·外部依赖」，非 PASS、非 FAIL，不计通过率（口径一贯）。
- **「269 条」是 Hermes/Linux 执行范围，非母版全量**：母版定义层全量 = 349 条（设计级 212 + 展开级 137），展开级 137 经 `init_day` 按 agent/OS 过滤后 Hermes/Linux 只下发 57 条，故执行范围 269 = 212 + 57。
- **迁移预演与补测分属两条执行包**：预演全量 269 条 + 补测 27 条，非同一批，勿相加当成「296 条」。
- **历史 commit 链**：`36ecfe7752`(候选设计) → `39f14e1adb`(Round-02 整改) → `fb93c00fea`(评审闭环) → `9725678ffa`(设计快照) → `0f86acbf6e`(生成器+门禁) → `afb2353728`(迁移预演) → `fdd3dcc44e`(补测闭环)，全部在 `origin/main` 可追证。
