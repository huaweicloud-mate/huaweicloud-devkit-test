## 二、待提单缺陷（9 条）

### P0 · 1 条

#### 1. D4-15　hook 绕过尝试 —— 写操作被 URL 编码绕过，拦截失效

| 项 | 内容 |
|---|---|
| 用例在做什么 | 验证危险写操作（例如删除云服务器）一定能被安全 hook 拦截，不允许任何绕过 |
| 问题现象 | 把命令里的「Delete」写成 URL 编码 `%44elete`，hook 就认不出来了——本该拦下的删除操作被放行（`allow/unknown_read`）。攻击者或模型可用此法绕过写操作 pre-check，直接打到 hcloud 写 API |
| 根因 | `plugins/huaweicloud-core/src/safety/classify-hcloud.ts:120`——`hasWritePrefix` 在命令 token 上直接匹配，**没做 URL 解码**，所以 `%44elete` 匹配不到 `Delete` 前缀 |
| 影响面 | 安全红线；Node / Python 双 hook 都受影响 |

### P1 · 7 条

#### 2. D8-9　安装 ID 与遥测值脱敏 —— 敏感凭证没被脱掉

| 项 | 内容 |
|---|---|
| 用例在做什么 | 遥测里生成的 installId 应稳定持久，并对含 AK/SK/token 形态的敏感值做脱敏 |
| 问题现象 | `sanitizeValue` 能处理控制字符/超长截断，但**漏删 AK/SK/token 形态的值**，明文凭证可能混进遥测 installId 外发 |
| 根因 | `telemetry/telemetry-values.ts`（sanitizeValue 家族）缺 AK/SK/token 敏感匹配 |

#### 3. D1-67　Agent toolkit 模式与跳过安装 —— 环境变量改名 + 跳过开关失效

| 项 | 内容 |
|---|---|
| 用例在做什么 | `AGENT_TOOLKIT_MODE` 应注入 agent 环境、`SKIP_DSH=1` 应跳过 DSH 插件安装 |
| 问题现象 | v2 把变量**改名**了，按 1.x 契约注入旧名不生效；`SKIP_DSH` 跳过分支在 v2 安装链路丢失 |
| 根因 | `mcp-config-io.ts:156` + `mcp-config-merge.ts:139`（`REQUIRED_ENV_KEYS`）改名为 `HUAWEICLOUD_AGENT_TOOLKIT_MODE`；SKIP_DSH 语义未保留 |
| 备注 | 属契约漂移（SPEC 级），**D9-13**（policy.version 未填，轻微）一并并入此条契约更新 |

#### 4. D3-S5　场景复合意图分层路由 —— 复合意图没拆成多个服务

| 项 | 内容 |
|---|---|
| 用例在做什么 | 复合意图（如「存储 + 托管」）应正确拆成多个服务、命中多个对应的华为云服务 |
| 问题现象 | 只返回**单一服务**，没有做多服务拆分，复合部署意图路由不完整 |
| 根因 | `huaweicloud_service_catalog` 路由层（gate 放行后）单服务归约逻辑，缺多服务拆分 |

#### 5. D3-C14　沙箱 hwlink 凭证 —— 连接没带签名头

| 项 | 内容 |
|---|---|
| 用例在做什么 | hdkit 透传参数、凭证校验要正确，`createConnection` 应带 `x-security-token` 签名头 |
| 问题现象 | 参数透传/凭证校验都 OK，唯独 `createConnection` **没带签名头**，真实云链接可能被拒 |
| 根因 | `lib/hdkit/hwlink-api.js`（v2）createConnection 签名头生成分支缺失/未生效 |

#### 6. D4-25　Python hook 事件遥测 —— 事件没落盘

| 项 | 内容 |
|---|---|
| 用例在做什么 | hook 拦截读/写/其他操作后，应写遥测事件（含 key/value/capability）供回溯 |
| 问题现象 | `hook-events.jsonl` 落盘 **0 条**，hook 决策无法回溯（拦截行为本身正常，只是没记账） |
| 根因 | `telemetry/hook-ingest.ts` / `telemetry.ts:97`（hookEventsPath）落盘链路未触发 |

#### 7. D1-60　HTTP 查询与自定义 registry —— 超时中止不生效

| 项 | 内容 |
|---|---|
| 用例在做什么 | registry 无响应时，升级检测应 ~400ms 超时后返回 null，不抛错、不卡死 |
| 问题现象 | 指向挂起不响应的 registry 时，2.5s 内既不返回也不抛错，返回超时哨兵 `__STILL_PENDING__`——abort 没真正中断底层 fetch |
| 根因 | `dist/update-check.js` `queryDistTagsFetch` 的 `AbortController`/signal **未接进** `fetchWithProxy` 调用 |

#### 8. D7-5　与既有配置共存 —— 安装会遮蔽用户自定义 MCP 配置

| 项 | 内容 |
|---|---|
| 用例在做什么 | 安装/升级不覆盖、不破坏用户已有的自定义配置 |
| 问题现象 | 首次安装（或已装他方 MCP 的环境）时，追加了第二个顶层 `mcp_servers:` 键，YAML「last-wins」导致**用户自定义 server 被遮蔽丢失** |
| 根因 | `dist/agents/hermes-config.js:54-86` `writeHermesMcpConfig`——只有当既有配置同时含 `mcp_servers:` 和 `huaweicloud-devkit` 才走合并；否则直接追加，产生重复键 |
| 影响面 | 用户数据破坏类缺陷 |
