## 一、结论摘要

用户反馈集中在两类问题，可归为 **5 类根因**：

1. **登录是"隐形门槛"** —— 插件唯一入口是 `npx huaweicloud-devkit auth init`，用户只有在云操作失败时才会被动发现"还没登录"。
2. **登录后"看不见自己是谁"** —— 凭据有 6 层优先级（runtime > S1-session > env > 码道 > S1 > KooCLI），但 `auth_status` 没有"当前生效账号来源 + 区域"的显式字段，用户只能自己推断。
3. **切换账号语义反直觉** —— `temporary / persist / clear` × `import / memory / mcp-config` 组合复杂，"临时切换不影响 hcloud、重启即失效"这类关键差异只写在英文工具描述里。
4. **错误与提示不够"可动作"** —— 关键文案（登录提示、hook 拦截、IAM 401）为英文；region 缺失要到 OBS 写入时才暴露；用户拿到报错不知道下一步做什么。
5. **闭环缺失** —— 登录后没有"体检"确认可用；安装/更新后"必须重启会话"只在 CLI 输出和 README 里，会话内不可见；首次登录后没有示例任务。

对应 **11 条改善需求（UX-R1 ~ UX-R11）**，其中 P1 八条、P2 三条。全部需求均配有可判定的验收断言，落成 21 条体验用例（D11-1 ~ D11-21）。

## 三、登录体验：痛点 → 改善需求

### UX-R1 未登录时的会话内引导（P1）

| 项 | 内容 |
|---|---|
| 现状 | 无凭据时 `resolveCredentials` 抛 `HDKIT_CRED_MISSING`，`message` 为英文长句；`err.onboarding` 虽带中文 `message` 与 `steps[]`，但 `steps` 里"去控制台取 AK/SK"是抽象动作，用户仍需自行拼装 |
| 期望行为 | 任一云能力工具在未登录时返回**中文结构化引导卡**：①一句人话说明"尚未登录"；②"去哪拿 AK/SK"（华为云控制台 → 我的凭证 → 访问密钥）；③两条可执行路径（CLI `npx huaweicloud-devkit auth init` / 会话内 `huaweicloud_auth_init`）；④安全声明（AK/SK 不进会话、不进 shell 历史） |
| 验收标准 | `err.code=="HDKIT_CRED_MISSING"`，`onboarding.scenario==3`，`onboarding.message` 含中文，`steps[]` 同时含 `obtain-aksk`（label 含"控制台"）与 `auth-init` 动作 |
| 依据 | `credentials.mjs:266-304`；`service.mjs:142-159` |
| 用例 | D11-1、D11-2 |

### UX-R2 当前生效账号可见（whoami）（P1）

| 项 | 内容 |
|---|---|
| 现状 | `getAuthStatus` 返回 `credentialsConfigured`(bool)、`reconciled.stores`(四组指纹)、`onboarding.accountHint`；**无显式的"当前生效来源 / 账号指纹 / 区域"字段**，也没有"本会话实际用哪个账号"的结论 |
| 期望行为 | `huaweicloud_auth_status` 增加 `effective` 字段：`{source, fingerprint, region, accountType}`，`source ∈ runtime / s1-session / env / codearts / s1 / koocli`，`accountType ∈ permanent / temporary`；并在首次云操作或用户询问时以一行中文回显 |
| 验收标准 | 4 组环境（runtime / S1-only / env 三件套 / S1+env）分别返回唯一 `effective.source`；`fingerprint == sha256(ak+sk)[:8]`；`region` 与来源一致；返回体无 AK/SK 明文 |
| 依据 | `service.mjs:165-186`；`reconcile.mjs:151-169`；`credentials.mjs:396-407` |
| 用例 | D11-3、D11-4、D11-5 |

### UX-R3 冲突态账号对照与一键选择（P2）

| 项 | 内容 |
|---|---|
| 现状 | S1 与 env 同时持有时 `scenario==2`，message 是"检测到两套账号…请选择其一"，但选项 label 为"使用已保存账号覆盖 / 使用环境注入账号导入"，用户无法知道两套账号分别是什么 |
| 期望行为 | 冲突时返回两组账号的 **指纹 + 区域 + 来源** 对照；选项用中文并各自带上指纹（"使用已保存账号（指纹 ab12cd34，区域 cn-north-4）"）；选择后经 `auth_confirm` 一键确认闭环 |
| 验收标准 | `onboarding.scenario==2` 且携带两组 `{fingerprint,region,source}`；`auth_switch persist` 返回 `needs_confirmation==true` + `confirmToken` + 中文 label；confirm 后 S1/env/S3 指纹一致 |
| 依据 | `service.mjs:94-129`；`tools.mjs:554` |
| 用例 | D11-6、D11-7 |

### UX-R4 切换语义与持久性显式化（P1）

| 项 | 内容 |
|---|---|
| 现状 | `auth_switch` 的 `action×mode` 组合（3×3）只用一段英文描述说明；`temporary` 的三个关键副作用（重启失效 / hcloud 不受影响 / 触发 A+C 警告）藏在描述里，极易误用 |
| 期望行为 | 切换返回**显式三元组**：`{scope, persistsAfterRestart, affects:{mcp,hcloud,obs}}`，并附中文提示（如"本次仅本会话生效，重启会话后需重新登录；hcloud 命令行不受影响"） |
| 验收标准 | `temporary` → `persistsAfterRestart==false` 且 `affects.hcloud==false` 且返回含中文警告字段；`persist` → `persistsAfterRestart==true` 且 `S1.configuredBySession==true`；`clear` → `effective.source` 回退到 `s1` |
| 依据 | `tools.mjs:537-552`；`credentials.mjs:194-198`（`setConfiguredBySession`） |
| 用例 | D11-8、D11-9 |

### UX-R5 登录流程母语化 + region 显式化 + 登录即校验（P1）

| 项 | 内容 |
|---|---|
| 现状 | ① 交互提示全英文：`Access Key ID (AK): ` / `Secret Access Key (SK): ` / `Security Token (optional, press Enter to skip): `；② region **不询问**，直接硬编码 `cn-north-4`，用户既不知道可以改、也不知道当前用的哪个；③ AK/SK **不做任何前置校验**，写错要等到后续云操作才暴露；④ 非 TTY 环境直接报英文提示退出 |
| 期望行为 | ① 四类提示中文化；② 显式询问 region（默认 `cn-north-4`，可回车跳过，并说明"不确定可用默认值"）；③ 输入后调用已有能力 `validateIamCredentials` 做一次只读校验，失败给中文可动作提示；④ 非 TTY 分支的中文提示同时给 CLI 与 MCP 两条路径 |
| 验收标准 | 四类提示均含中文字符；region 缺省时不出现 `region, ak, and sk are required`；无效 SK 返回中文 401 语义提示 + 「控制台重新生成访问密钥」动作，且不出现英文 `IAM rejected the credentials` 裸串 |
| 依据 | `setup-cli.mjs:4790-4856`；`credential-validator.mjs:90-163`；`credentials.mjs:205` |
| 用例 | D11-10、D11-11、D11-12、D11-15 |

### UX-R6 登录后闭环自检（P1）

| 项 | 内容 |
|---|---|
| 现状 | `auth init` 完成只打印 "Credentials synchronized." + 两句英文 next steps；S1 / OBS / KooCLI / project-id / MCP 注册五个端口的就绪状态分散在 `auth_status` 各字段里，用户无法一眼判断"现在到底能不能用" |
| 期望行为 | 登录后（或显式调用 `auth_status`）返回**中文体检卡**：五项 ready 状态 + 每项失败时的**唯一定向 nextStep 命令** + "是否需要重启会话"结论 |
| 验收标准 | 干净登录后五项 `ready==true` 且 `nextStep` 为空；单端破坏（如删 `~/.obsutilconfig`）时该项 `ready==false` 且 `nextStep` 唯一含 `huaweicloud_auth_sync`，其余四项仍 true |
| 依据 | `service.mjs:165-186`、`188-218`；`reconcile.mjs:106-170` |
| 用例 | D11-13、D11-14 |

## 四、使用体验：痛点 → 改善需求

### UX-R7 统一错误卡：中文化 + 可动作化（P1）

| 项 | 内容 |
|---|---|
| 现状 | 错误文案散落在各模块且为英文：`Huawei Cloud credentials are not configured...`（`credentials.mjs:266`）、`IAM rejected the credentials (HTTP 401...)`（`credential-validator.mjs:144`）、`KooCLI not ready.`（`service.mjs:238`）、`Huawei Cloud safety hook blocked this action:`（`huaweicloud-safety.py:20`）；且 region 缺失只在 `writeObsConfig` 抛 `region, ak, and sk are required` 才暴露 |

| 验收标准 | 6 码均返回非空 `messageZh`（含中文）与非空 `action`（以 `npx huaweicloud-devkit` 或 `hcloud` 开头）；6 码 `action` 互不相同 |
| 依据 | `service.mjs:191-251`；`credentials.mjs:264-269`；`credential-validator.mjs:139-162` |
| 用例 | D11-16 |

## 七、验收口径（避免"评估完成 ≠ 已实现"）

1. 每条需求以对应 D11 用例的**唯一断言**判定，不采信"已优化/已支持"的自述。
2. 涉及源码的断言必须**读到实现**（`git log --all -S <字段名>` 确认已落地），方案冻结不算实现。
3. 体验类断言（中文文案、示例任务）以**脱敏返回体原文**为证据，落 `results/<客户端>/<日期>-<IP>/<OS>/evidence/`。
4. 本轮为**需求提案**，未提上游 issue；待评审通过后按「全量测完合并一张单」口径与既有 D11 用例一并归档。

## 九、方法论边界（诚实声明）

1. **体验用例是回归门禁，不是体验验收**。它能证明"文案对了、字段有了、闭环成立"，证明不了"用户更快完成任务"。
2. 三类体验**无法用断言覆盖**，需人工 rubric：认知负荷、错误文案"够不够新手用"、视觉排版。
3. 依赖新契约的 11 条用例（见 `依赖` 列 `契约依赖: … 待冻结`）在契约冻结前应标 `NOT_RUN`，**不得以 `DESIGN_COVERED` 混淆**为"已通过"。
4. 剩余 21 个缺口（含 4 个 P1）已登记，待评审决定归属，**不以堆用例充数**。
