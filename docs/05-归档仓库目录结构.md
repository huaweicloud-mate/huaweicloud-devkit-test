# 测试归档 GitHub 仓库 — 目录结构规划（v1.0）

> **目的**：把 huaweicloud-devkit 测试体系（规划/用例/模板/执行结果/度量/评测）从本地散文件升级为**可归档、可追溯、可复现**的 GitHub 仓库。
> **被测对象**：https://github.com/huaweicloud/huaweicloud-devkit（仅测试资产入库，不含插件源码）
> **规划依据**：测试规划 v1.3 §9 交付物清单、§5.1 度量体系、§5.2 用例演进铁律

---

## 一、设计原则（5 条红线）

1. **凭证零进入**：AK/SK、.agents、.hcloud、obsutilconfig、.env 永不入库——`.gitignore` 是第一道闸，`evidence/` 只存脱敏内容。
2. **模板、评审与结果分离**：`templates/` 静态不变体；`reviews/` 保存设计评审；`results/` 保存实际执行结果。
3. **版本化可追溯**：每轮迭代一个目录（`ITER-NNN-时间戳`），基线 commit 必记，报告含目标 commit。
4. **可复现**：用例矩阵由 `gen_matrix.py` 生成、评测 harness 与评测集入库，任何人 clone 后可重跑。
5. **与上游解耦**：本仓库 = 测试侧资产；插件缺陷通过 issue 提交到上游，本仓库只留拆分稿。

## 三、命名规则（一致性=可追溯）

| 对象 | 规则 | 示例 |
|---|---|---|
| 迭代目录 | `ITER-<NNN>-<YYYYMMDDHHmmss>` | `ITER-001-20260905000000` |
| 每晚报告 | `nightly-<YYYYMMDDHHmmss>.md` | `nightly-20260905000000.md` |
| 客户端矩阵 | `matrix-<vX.Y.Z>.md`（对应被测插件版本） | `matrix-v1.2.0.md` |
| 评测集 | `eval-set-v<N>.csv` | `eval-set-v1.csv` |
| 缺口表 | `gaps-<ITER>-<YYYYMMDDHHmmss>.md` | `gaps-ITER-001-20260905000000.md` |
| 测试规划 | `01-测试规划.md`（去版本号，演进靠 git） | — |
| 用例 ID | `Dx-y` 体系，§5.2 三铁律（ID 永不复用/OBSOLETE/supersedes） | `D11-1` |

## 七、与上游的协作流（避免双轨）

```
本仓库 reviews/ITER-NNN/          → 设计评审和 TEST_DESIGN_READY 结论
本仓库 results/ITER-NNN/issues/   → 执行阶段发现的 issue 拆分稿（§6.4 模板）
        ↓ 人工确认 + 脱敏复核
上游仓库 huaweicloud/huaweicloud-devkit issues  → 提交
        ↓
上游合入修复 → 本仓库下迭代回归验证（P0-5 续号，§6.2 闭环）
```
