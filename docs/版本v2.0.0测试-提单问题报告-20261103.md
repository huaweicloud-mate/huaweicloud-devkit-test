## P0 · 1 条

### 1. D4-15　hook 绕过尝试 —— 写操作被 URL 编码绕过

**这句用例在测什么**

devkit 有一条安全 hook，用来拦截危险写操作（比如删除云服务器）。这条用例专门做「对抗性验证」：拿一个 `DeleteServers` 命令，各种混淆它——改大小写、URL 编码、把参数拆开拼——然后要求 hook **每一种变体都必须拦下，不允许任何绕过成功**。

**实际出了什么问题**

原形 `DeleteServers`、大小写变体 `deleteservers`，hook 都正确判 `deny/write` 拦下了。但把中间一段写成 URL 编码——`hcloud ECS %44elete%53ervers --server-id i-1`——hook 就认不出来了，把它判成 `allow/unknown_read` **放行**了。

**根因**

`safety/classify-hcloud.ts:120`：`hasWritePrefix` 直接拿原始 operation token（`commandOperation` 在 `:51` 取出）去匹配 `Delete` 前缀，**没有做 `decodeURIComponent` 解码**，所以 `%44elete`（= Delete）匹配不到，绕过成立。Node / Python 双 hook 都走这一判定。

**影响面**

安全红线：攻击者或模型可用 URL 编码写操作 token 绕过写操作 pre-check，直接打到 hcloud 写 API。**P0**。

## P1 · 7 条

### 2. D8-9　安装 ID 与遥测值脱敏 —— 敏感凭证没脱掉

**这句用例在测什么**

插件会生成一个安装 ID（installId）用于遥测上报。这条用例要求两点：① ID 生成后稳定持久（二次调用不漂移）；② `sanitizeValue` 能把值里的敏感凭证（AK/SK/token）和非法字符**摘掉**，同时不碰合法值。

**实际出了什么问题**

`sanitizeValue` 能移除控制字符、截断超长、保留合法值，唯独**漏删了 AK/SK/token 形态的值**——明文凭证可能混进遥测 installId 外发。

**根因**

`telemetry/telemetry-values.ts`（sanitizeValue 家族）缺 AK/SK/token 敏感 pattern 匹配。

**影响面**

遥测 installId 可能携带明文凭证片段，PII 泄露风险。**P1**。

### 3. D1-67　Agent toolkit 模式与跳过安装 —— 环境变量改名 + 跳过开关失效

**这句用例在测什么**

通过环境变量控制安装行为：`AGENT_TOOLKIT_MODE=local` 应注入 agent 环境（进 REQUIRED_ENV_KEYS），`SKIP_DSH=1` 应跳过 DSH 插件的安装。

**实际出了什么问题**

v2 把这个变量**改名**成了 `HUAWEICLOUD_AGENT_TOOLKIT_MODE`——按 1.x 契约注入旧名 `AGENT_TOOLKIT_MODE` 完全没命中；`SKIP_DSH` 跳过分支在 v2 安装链路里也丢了语义，DSH 插件照装不误。

**根因**

`mcp-config-io.ts:156` + `mcp-config-merge.ts:139`（`REQUIRED_ENV_KEYS`）改名为 `HUAWEICLOUD_AGENT_TOOLKIT_MODE`；SKIP_DSH 分支未保留。

**影响面**

安装域环境注入/跳过开关与 1.x 契约漂移，属 SPEC 级。**P1**。附带 D9-13（`policy.version` 未填、`undefined`，轻微契约漂移）一并并入此条契约更新，不单列。

### 4. D3-S5　场景复合意图分层路由 —— 复合意图没拆成多路

**这句用例在测什么**

用户一句话提多个诉求：「物联网 + 时序数据 + 前端托管，先预览后生产部署」。插件应把这句**复合意图拆成多路**：物联网/时序数据 → 存储类（DDS/GaussDB/MongoDB），前端托管 → 部署类（OBS/ECS/CCE），并做预览/生产分层推荐（预览走沙箱、生产走 ECS），不能只吐一个服务。

**实际出了什么问题**

提交这句复合意图后，`serviceCatalog` 返回的 `recommendedServices` **没拆成多路**——存储类与托管类**没有同时命中**（探针 `hitStorage && hitHosting` = false，多路命中数 < 2），只归约成了单一服务，另一路诉求被丢。证据 FAIL 原话：「复合意图拆分未命中多个 service（存储+托管）——serviceCatalog 路由拆分为单一服务，缺乏复合意图多服务拆分」。

**根因**

`huaweicloud_service_catalog` 路由层（vendor gate 放行后）对复合意图采用**单服务归约逻辑**，一个 intent 只归约到一个 primary service，无「多服务拆分」分支。

**影响面**

真实用户一句话说「存时序数据再托管前端」，插件只推荐单一服务，得用户自己拆成多句重问，路由体验降级。功能缺陷、非红线，**P1**。

### 5. D3-C14　沙箱 hwlink 凭证 —— 连接没带签名头

**这句用例在测什么**

沙箱 HDKit 服务链路：`hdkitConnect` 透传可选参数到 body；`hdkitCredentials` 缺 `sessionId`/`devStageId` 时报错；`getCredentials` 返回 `{ak,sk,securitytoken}`；`createConnection` 用 securitytoken 走 `x-security-token` 签名头完成握手。

**实际出了什么问题**

参数透传、缺参报错、getCredentials 返回三元组——这些都 OK。唯独最后一步 `createConnection` **没带 `x-security-token` 签名头**。

**根因**

`lib/hdkit/hwlink-api.js`（v2）createConnection 的签名头生成分支缺失/未生效。

**影响面**

hwlink 连接握手签名不规范，真实云链接可能被拒。**P1**。

### 6. D4-25　Python hook 事件遥测 —— 事件没落盘

**这句用例在测什么**

Python 安全 hook 拦截命令后，应把事件写到 `hook-events.jsonl` 遥测文件：只读 → `cli:read`、写 → `cli:write`、其他 → `cli:invoke`，事件含 key/value/capability，供事后审计回放。

**实际出了什么问题**

`hook-events.jsonl` **落盘 0 条**（new-safety-probe 读到 null 直接崩）。hook 的 deny 拦截行为本身正常（D4-28 已验证），**只是事件没记账**。

**根因**

`telemetry/hook-ingest.ts` / `telemetry.ts:97`（hookEventsPath）落盘链路未触发。

**影响面**

hook 审计/遥测事件缺失，无法回溯 hook 决策。**P1**。

### 7. D1-60　HTTP 查询与自定义 registry —— 超时中止不生效

**这句用例在测什么**

升级检测的 fetch 路径应走自定义 `HUAWEICLOUD_NPM_REGISTRY`（去尾斜杠）；registry 无响应/故障时，应在 ~400ms 超时后 abort、返回 `null` 而不抛错，且不与 spawn 路径（`npm view`）混用。

**实际出了什么问题**

指向一个「挂起不响应」的 registry 时，2.5 秒内既不返回也不抛错，返回值是超时哨兵 `__STILL_PENDING__`——**abort 触发了，但底层 fetch 没被真正中止**，Promise 一直挂到外层兜底。

**根因**

`dist/update-check.js` `queryDistTagsFetch` 的 `AbortController`/signal **没有接进** `fetchWithProxy` 调用。

**影响面**

registry 无响应/网络故障时升级检测挂起，影响 `check_update`/安装器升级通道健壮性（正常 registry 路径与去尾斜杠逻辑均 PASS，仅超时分支失效）。**P1**。

### 8. D7-5　与既有配置共存 —— 安装会遮蔽用户自定义 MCP 配置

**这句用例在测什么**

安装/升级插件**不得覆盖、不得破坏**用户已有的自定义配置——升级前备份 profile 与 MCP 配置，升级后核对用户自定义内容原样保留。

**实际出了什么问题**

在隔离 HOME 里预置了用户自定义 `mcp_servers.my-custom-server` + 自定义字段，`install --target hermes` 后追加了**第二个顶层 `mcp_servers:` 键**；`PyYAML safe_load`（last-wins）解析后 `my-custom-server` **丢失**（自定义 `markers` 字段倒是保留了）。

**根因**

`dist/agents/hermes-config.js:54-86` `writeHermesMcpConfig`：只有当既有配置**同时**含 `mcp_servers:` 和 `huaweicloud-devkit` 才走「移除旧块重写」合并；用户已有自己的 `mcp_servers` 但尚无 `huaweicloud-devkit` 条目时（首次安装/已装他方 MCP），条件不成立 → 直接 `${existing.trimEnd()}\n\n${newBlock}` 追加，产生 YAML 重复顶层键。

**影响面**

首次安装或已装他方 MCP 的用户，其自定义 MCP server 被遮蔽丢失。**用户数据破坏类缺陷，P1**。

## P2 · 1 条

### 9. D3-C10　市场分类列表 —— 返回空（上游索引弃用）

**这句用例在测什么**

市场分类列表应完整，且与 `searchMarketplace(category)` 的分类过滤结果一致。

**实际出了什么问题**

`getMarketplaceCategories()` 机制正常（`ok:true`）但返回 `categories: []` 空列表；`searchMarketplace('')` 空查只返回一条迁移指引「请升级到最新 huawei-cloud-find-skills」。市场分类导航能力事实失效。

**根因**

`dist/search-market.js:3` `INDEX_URL` 仍硬编码指向**已弃用**的 gitcode 索引 `2501_91318609/skills-for-index`（`deprecated=true, total_skills=0`），未迁移到新索引源（`huaweicloud/huaweicloud-skills`）。

**影响面**

市场分类/按分类过滤能力不可用，只能拿迁移指引；属上游数据源驱动，非 v2 代码回归。**P2**。
