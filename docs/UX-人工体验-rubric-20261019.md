# UX 人工体验 rubric（断言覆盖不到的三类）

| 项目 | 内容 |
|---|---|
| 生成时间 | 2026-10-19 19:15:00（北京时间） |
| 来源 | `docs/UX-体验用例-覆盖自审-20261013.md` §六「诚实边界：断言覆盖不到的部分」 |
| 定位 | **人工可用性验收增量**，与自动化门禁（D11 夹具 / 回放 / 度量对照）**口径分开、不互相替代** |
| 使用时机 | 候选发版前一次（或体验相关改进落地后一次）；不进入 CI，不做门禁 |

> 自动化能证明「某处文案对了、某条命令可执行、某指标不劣化」，**证明不了**「用户更快/更少困惑地完成任务」。
> 本 rubric 就负责后者，代价是必须人工打分并留存证据。

## 一、五个维度与判据

| # | 维度 | 判据（0 / 1 / 2 分） | 证据要求 |
|---|---|---|---|
| A | **认知负荷** | 2 分：从安装到首次成功只读调用，新用户需理解的新概念 ≤3 个且不含内部代号；1 分：≤5 个或出现 1 处内部代号；0 分：>5 个或内部代号 ≥2 处 | 录屏（从 `install` 到首次调用成功，同一会话不查文档） |
| B | **错误文案够不够新手用** | 随机抽 5 条真实错误：2 分 = 5 条都能让未读文档的人 2 分钟内说出「下一步做什么」；1 分 = 3~4 条；0 分 = ≤2 条 | 5 条错误原文 + 每条的「人工判断耗时」 |
| C | **视觉与排版** | 2 分：CLI 表格对齐、无颜色环境下语义不丢、客户端内渲染不错位；1 分：有 1 处影响阅读；0 分：≥2 处或导致结论不可读 | 截图（终端 + 客户端内各一）+ `NO_COLOR=1` 对照截图 |
| D | **引导闭环（人工复核「够不够用」）** | 2 分：按引导完成登录/修复后症状消失，且引导步骤 ≤3 步；1 分：≤5 步；0 分：>5 步或需外部文档 | 引导原文（`ready`/`nextStep`）+ 逐步执行录屏 |
| E | **度量对照（引用 D11-40，人工解读）** | 2 分：三指标均不劣化且至少一项严格改善；1 分：不劣化无改善；0 分：任一项劣化 | `eval/results/ux-loop-*.json`（≥3 次采样取中位） |

> 维度 D 与自动化断言的关系：D11-37/D11-41 断言的是「按 `action` 执行后症状消失」（可自动判定），
> 本维度判的是「**这个引导对新手够不够**」（只能人工）——同一场景、两个口径。

| 维度 | 得分(0-2) | 权重 | 加权 | 证据路径 |
|---|---|---|---|---|
| A 认知负荷 | | 0.25 | | |
| B 错误文案可操作性 | | 0.25 | | |
| C 视觉与排版 | | 0.15 | | |

**通过建议线**：加权 ≥1.5 且无任一维度为 0。任一维度 0 分 → 记为该版本体验**不可接受**，需在改善需求里单列。

## 三、与自动化门禁的关系（勿混口径）

| 口径 | 载体 | 结论形态 | 是否门禁 |
|---|---|---|---|
| 回归防退化（自动） | D11 夹具 41 条 + `run-ux.mjs` | PASS / NOT_IMPLEMENTED / NOT_RUN / BLOCKED | CI 趋势（实现到位后转硬门禁） |
| 文案退化趋势（自动） | `eval/replay/ux-replay.mjs` | 语义分类 CSV | CI 趋势 |
| 度量对照（自动采集 + 人工解读） | `eval/harness/ux-agent-loop.mjs` | 三指标对照表（≥3 采样） | 否 |
| **人工体验验收** | **本 rubric** | 加权得分 + 证据 | **否（人工评审）** |

## 四、维护

- 判据若被自动化替代（例如「步骤数」可由 D11-40 精确采集），应把该维度**降级或删除**，避免双重口径。
- 每次评审后把「行动项」回写 `docs/UX-改善需求清单-RFE-*.md`（若属新能力）或既有缺陷单（若属实现缺陷）。
